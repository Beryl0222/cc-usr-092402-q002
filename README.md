# 群众赛事医疗资源编排

群众赛事医疗保障的**可版本化覆盖演练与发布流程**。所有状态变化都是不可变事件；
覆盖计算是纯函数；方案经「草稿 → 演练 → 审批 → 发布」流转，审批后仍可针对突发
高温、道路封闭、设备失效做局部重算。资料只包含领域约定与虚构样例，不含真实个人
信息、生产连接或外部账号。

## 解决的问题

- 路线临时调整后，纸面救护车/急救点数量没变，却可能被封路切断——每次演练/回放都在
  **当时生效的封路集合**上重算行驶时间，逐段给出达标证据或缺口类型（超时、不可达、
  无资质、无救护车、医院名额已满）。
- 方案为什么在某时段满足响应目标，可用报告中每个时间片的证据链复核（密度/风险/高温
  如何决定目标、谁负责、行驶秒数、医院名额）。
- 演练建议**不会**自动覆盖已发布方案；只有显式发起修订、审批、发布才生效。
- 同一资源在重叠时段只能被一个方案占用；同一版本重复发布幂等，资源不会被占用两次。
- 人工选择比系统更慢的路径时，`ROUTE_CHOSEN` 必须携带理由，入库即校验并留痕。
- 无线网络中断期间缓存的位置/伤情消息，恢复后按**来源单调序号**合并；缺口未补齐时
  后续消息保持缓冲；已完成转运是吸收态，迟到的旧消息不能把事实回退。
- 外部志愿者只能看到执行所需信息（本人值守段、报到节点、本人提醒），看不到医院容量、
  他人安排和内部替代推演。
- 班次跨日、资质在值守中途到期/被吊销，都会在覆盖报告中形成「无人负责段」；审批闸门
  要求每个缺口逐条签署书面豁免，否则版本不能冻结。
- 现场指挥可重播任一方案版本，得到当时各段覆盖缺口、获批替代资源、实际转运偏差。

## 目录

- `src/events.js`：事件目录、字段校验、版本图。
- `src/time_windows.js`：半开区间工具（重叠、切片、并集覆盖、缝隙）。
- `src/risk.js`：密度/风险/高温 → 响应目标与预期负荷。
- `src/network.js`：路网、封路、最快路径、人工路径校验（慢路径强制理由）。
- `src/coverage.js`：覆盖计算引擎（纯函数）与基线/情景差异。
- `src/registry.js`：事件溯源注册表、方案生命周期、审批闸门、资源占用账本。
- `src/field_messages.js`：断网消息按来源序列合并、转运事实单调性。
- `src/replay.js`：版本视图、演练、版本回放、转运偏差、志愿者最小视图。
- `data/sample.json`：虚构事件格式样例。
- `tests/`：26 个场景测试（跨日班次、封路、高温、设备失效、医院容量、占用冲突、
  幂等发布、断网合并、事实回退防护、志愿者脱敏等）。

## 事件生命周期

```
EVENT_RISK_FILED / RESOURCE_DECLARED / HOSPITAL_CAPACITY_FILED
        │
   PLAN_DRAFTED ── AID_STATION_OPENING_SET / RESOURCE_DECLARED / ROUTE_CHOSEN
        │
   PLAN_DRILL_RUN（只读：在假设封路/高温/失效上重算，产出缺口与替代建议）
        │
   PLAN_APPROVED（审批闸门：全赛期覆盖核验，缺口须逐条 gap_waivers 豁免）
        │
   PLAN_PUBLISHED（产生资源占用；同 version_id 重发幂等）
        │
 突发情况：ROUTE_CLOSURE_FILED / WEATHER_ALERT_FILED /
          EQUIPMENT_FAILURE_FILED / QUALIFICATION_REVOKED
        │
   PLAN_REVISED（基于当前最新发布版本局部重算）→ 审批 → 发布（生效时取代祖版占用）
```

现场侧：`INCIDENT_ESCALATED`、`FIELD_MESSAGE_RECEIVED`（断网缓存回传）、
`HANDOFF_COMPLETED`（转运完成的权威事实）。
