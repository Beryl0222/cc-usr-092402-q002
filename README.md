# 群众赛事医疗资源编排

本项目用于整理群众赛事医疗资源编排领域中的事件名称、交换字段与脱敏样例，方便业务、运营和研发人员在同一套术语下讨论后续服务。资料只包含领域约定，不包含真实个人信息、生产连接或外部账号。

在此之上，项目提供一套可版本化的覆盖演练与发布流程：路线分段、观众密度、风险等级、急救点开放窗、车辆与人员资质、医院接收能力及行驶时间共同参与覆盖计算；方案审批发布后，仍能针对突发高温、道路封闭或设备失效做局部重算。

## 目录

- `src/race_medical_dispatch.js`：事件种类、最小字段校验与各模块的统一入口。
- `src/coverage.js`：覆盖计算核心，输出每个分段“为何满足/为何不满足”响应目标的书面依据。
- `src/disruptions.js`：突发扰动（高温/封路/设备失效）与局部重算、替代建议。
- `src/plans.js`：方案版本（草稿→审批→发布→废止）、资源占用台账与覆盖演练。
- `src/offline_merge.js`：断网期间位置/伤情/转运消息按来源序列合并。
- `src/volunteer_view.js`：外部志愿者的最小信息视图。
- `src/shifts.js`：跨日班次与资质中途到期的无人负责段校验。
- `src/replay.js`：按版本回放覆盖缺口、获批替代与转运偏差。
- `data/sample.json`、`data/samples/`：用于核对资料格式的虚构事件。
- `tests/`：保证样例与领域约定一致，并覆盖上述流程的关键不变量。

## 流程约定

1. **草稿与审批**：`draftVersion` 产生草稿版本，`approveVersion` 后方可发布；演练（`runDrill`）在受扰动的世界副本上评估已发布方案，建议只写入新的草稿版本，不能直接覆盖已发布方案。
2. **发布与占用**：`publishVersion` 通过占用台账原子申领资源——同一资源在重叠时段只能被一个已发布方案占用；重复发布同一版本幂等，不会重复占用；新版本发布后旧版本自动废止并释放占用。
3. **局部重算**：`partialRecompute` 只输出受扰动影响的分段及其最新覆盖；替代建议（`suggestSubstitutions`）优先使用未被占用的空闲合格资源，不足时请求外部增援，替代资源经 `SUBSTITUTION_APPROVED` 审批后随新版本生效。
4. **人工路径**：`validatePathChoices` 要求人工选择慢于当前最快路径时留下非空理由。
5. **断网续传**：`mergeMessages` 以 `(source_id, seq)` 去重并按来源序列合并；位置只保留各来源最新序号；转运状态单调推进，已完成转运事实不可被较晚到达的旧消息回退。
6. **最小可见**：`volunteerView` 只投影志愿者本人执行所需的岗位、窗口、任务与联络频道。
7. **排班校验**：`validateRoster` 归一化跨日班次，找出资质中途到期或排班缺口导致的无人负责时段。
8. **版本回放**：`replayPlan` 从事件流还原任一版本发布时的各段覆盖缺口、获批替代资源与实际转运偏差。
